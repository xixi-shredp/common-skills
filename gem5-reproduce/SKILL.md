# Gem5 复现设计约束

在 Gem5 上复现论文或者专利时，需要遵循以下约束：
1. 如果实现时存在无法精确实现的情况，必须向用户澄清，并给出你的近似处理策略
2. 只有实现了和论文对齐的所有任务点之后才可以停下来
3. 实现完之后，再单独开一个 subagent 来 review 设计：检查当前的复现实现和论文/专利原文描述的差异性
  - 如果存在差异，且差异难以实现，和用户沟通具体实现细节
  - 如果存在差异，但差异你可以解决时，继续补全差异，补全后重新执行步骤 3 继续 review 循环
  - 如果不存在差异，则认为复现完成
4. 实验验证：主要是端到端的性能验证，必须向用户询问性能验证的方式
5. 如果最终的实验结果表明，workload 不能正确运行完时，进行功能正确性修复
6. 如果最终的实验结果表明，性能收益原不及预期（如 prefetcher 实现的 accuracy, coverage 极低），分析当前性能反常的原因，并进行性能修复
7. 如果实验结果符合预期，将当前 Gem5 的实现整理成 markdown spec 文档写入当前工作目录（`doc/gem5-impl.md`）
