# Gem5 复现设计约束

在 Gem5 上复现论文或者专利时，需要遵循的约束

## Workflow

1. 阅读专利/论文，了解论文/专利的核心设计点
2. 根据专利/论文的核心设计点构思设计方案，可以使用 brainstorming skill
3. 确定可能的设计方案之后，检查以下情况：
    - 如果实现时存在无法精确实现的情况，必须向用户澄清，并给出你的近似处理策略
    - 如果实现时可能涉及到对其他组件的修改，必须停下来请求用户同意：
        - 修改父类，可能影响其他继承该父类的子类
        - 修改其他类，可能会影响其他类的功能正确性
4. 开始实现,只有实现了和论文对齐的所有任务点之后才可以停下来
5. 实现完之后，再单独开一个 review subagent 来 review 设计(参考 Review Agent Task)
  - 如果 Review 的结果满足 Task 要求，则进入步骤 6，否则修复 review 时存在的问题，然后继续开启 review subagent 检查，直接 review task 任务均已完成。
6. 实验验证：主要是端到端的性能验证，必须向用户询问性能验证的方式
7. 如果最终的实验结果表明，workload 不能正确运行完时，进行功能正确性修复
8. 如果最终的实验结果表明，性能收益原不及预期（如 prefetcher 实现的 accuracy, coverage 极低），分析当前性能反常的原因，并进行性能修复
9. 如果实验结果符合预期，将当前 Gem5 的实现整理成 markdown spec 文档写入当前工作目录（`doc/gem5-impl.md`）

## Review Agent Task

作为一个 review agent, 需要审查以下内容：

1. 检查当前的复现实现和论文/专利原文描述的差异性
    - 如果存在差异，且差异难以实现，和用户沟通具体实现细节
    - 如果存在差异，但差异你可以解决时，继续补全差异，补全后继续开启 review agent 进行验证，循环下去
2. 检查实现是否涉及到对其他组件的修改，是否会影响其他类的功能正确性
