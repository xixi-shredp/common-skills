# Write SPEC Docs

根据用户给定的输入(代码/文档)，介绍一下用户指定的相关设计, 重点体现用户要求体现的设计, 输出一套 spec 文档

## 要求用户至少输入

- [ ] 写 SPEC 文档的基础参考：指定的代码/文档路径
- [ ] 需要重点介绍哪些内容
- [ ] 输出目录 

## 输出 SPEC 文档要求

所有输出文档全部输出到用户指定目录下

注意：

- 输出的文档不一定是单个文档，考虑到代码的复杂性，可能需要按照代码的功能/层级分别写多个文档
- 每个文档要求内容足够全面，覆盖率足够高
- 格式为中文 markdown ，表述严谨，面向 CPU 体系结构工程师

## Steps

1. 阅读基础参考：代码/文档
    - 先确定顶层架构，自顶向下延伸到子模块
    - 根据不同的子模块任务划分为多个可以并行分析的任务
2. 根据划分的并行任务，拆分出不同的 subagent，所有 subagent 并行处理阅读分析
3. 汇总所有产生的文档，进行 review （如果需要 review 的文档较多，则拆分多个 subagent 并行 review）
    - review 要求：严禁输出内容和代码不一致，严禁不同输出文档之间存在矛盾、表述不严谨
